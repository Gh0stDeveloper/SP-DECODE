# SP-DECODE Android v1.0.8 — NPVS v5 complete JSON and production approval

**Release target:** `versionName=1.0.8`, `versionCode=19`, package `com.ghostdeveloper.spdecode`.  
**Requested:** 2026-10-10 by the project owner; explicit authorization to publish a **stable, public production APK** after successful CI and permanent-key signing.  
**Scope:** One Android-native decoder behavior update on top of stable v1.0.7; no retroactive assertion of independent vendor coverage.

## Implementation and parity

- Python authoritative reference: `decoders/Python/npvs.py::decode_npvs_complete` (PR #62, merged to `main`).
- Kotlin native entrypoint: `android/app/src/main/java/com/ghostdeveloper/spdecode/parity/NpvsPort.kt`.
- Kotlin field layer: `android/app/src/main/java/com/ghostdeveloper/spdecode/parity/NpvsEmbeddedFields.kt` (PR #63, merged to `main`).
- The signed **NPVS version 5 compact app-key** envelope still requires successful ECDSA P-256 signature verification, authenticated metadata, ChaCha20-Poly1305 field decryption, HMAC inventory and reference reconstruction before output.
- After authentication, explicitly marked `npvs1:` Base64 fields are decoded recursively (including nested JSON and UTF-8). Non-marked, Base64-looking credentials are intentionally retained; guesses can corrupt legitimate data. Corrupt marked values fail instead of returning misleading partial JSON.
- Signed synthetic NPVS v5 parity vectors are generated by `scripts/android_npvs_fixture_export.py`. Python `tests/test_npvs_v5_embedded.py` and Android API35 instrumented `NpvsSignedFixtureInstrumentedTest.kt` cover nested fields, multilingual text, multiline HTTP payloads, credential literals and tampered signatures.
- Real `Era tecnologica.npvs` (v5) was previously tested in Python with complete JSON, including seven embedded fields. Its private contents are **not** committed. Android verification here is based on independently generated synthetic fixture and emulator, **not** a documented physical-device rerun of the private file.

## Limits and outstanding evidence

- NPVS v6 recipient-ECDH and NPVS v1 are **not** supported by this specific v5 app-key decoder. A missing recipient key cannot be replaced by changing the version byte.
- No new external-format compatibility is claimed for the other 238 native suffixes.
- Physical ARM64 real-file rerun, 16 KiB devices, accessibility/performance measurements, independently reproduced current-vendor corpus and installed public APK upgrade logs remain pending unless separately documented.
- The previous v1.0.7 HTTP Injector full-JSON correction is retained unchanged.

## Owner production decision: version-scoped OWNER-GO

The project owner explicitly requested **v1.0.8 as a stable public production Release**, including this latest NPVS v5 correction, and asked to remove only obsolete publication blocks. Owner accepts the documented limits of manual and synthetic QA; this is **not independent validation** of all real exporters.

4. Verify 16 KiB ZIP alignment, package ID, `versionName=1.0.8`, SHA-256 and embedded source commit.

6. Release notes must disclose limits; approval is specific to 1.0.8 and does not carry to future versions.

**Owner approval is a release distribution decision, not a new claim that pending audit evidence has become verified.**
